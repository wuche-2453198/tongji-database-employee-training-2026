# 项目执行与人员分工

## 1. 目标、范围与成功标准

十人小组在 15 个工作日内交付一个可部署、可演示、可恢复数据的企业内部培训管理系统。系统采用 B/S 架构，前端只通过 HTTP API 访问 C# 后端，后端访问 Oracle 数据库。

演示主链路必须使用新生成的业务数据连续完成，过程中不得手工修改数据库：

```text
管理员维护部门、员工、讲师和课程
  -> 发布课程并占用部门预算
  -> 员工提交培训申请
  -> 本部门主管审批
  -> HR 备案
  -> 员工报名
  -> HR/管理员签到并完成培训
  -> 员工评分，HR 录入测试
  -> HR 生成证书
  -> 员工查询证书
```

项目成功需同时满足：空库脚本可执行、四类角色权限正确、前后端可统一启动、完整主链路可复现、演示数据可恢复、仓库中无敏感凭证。

## 2. 首期业务边界

首期只实现 2026 年单年度部门预算、一门课程一名主讲师、每次报名一次签到。以下内容保留扩展点但不阻塞首期：跨年度预算、多讲师课程、真实二维码设备、邮件/短信通知、复杂报表和微服务拆分。

固定业务决策：

- 所有报名必须引用同员工、同课程且状态为 `HR_FILED` 的申请；HR 备案不自动创建报名。
- 课程发布时事务性占用主办部门预算；发布后不得修改主讲师、主办部门、开始/结束时间、最大人数、学时和预算金额。
- 主管必须具有 `DEPT_MANAGER` 角色，且只能审批本部门员工的申请；管理员可代办。
- 生效黑名单、离职员工、未发布/已关闭/已开始课程均不可报名。
- 一条报名最多一条签到；实际学时由后端统一计算。
- 证书以 `COMPLETED` 报名为前置条件；课程配置训后测试时还要求 `POST >= 60`。
