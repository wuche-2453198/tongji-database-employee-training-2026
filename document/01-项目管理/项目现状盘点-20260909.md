## 8. 工程规范执行口径（摘要）

- **分支**：`main` 可演示 / `develop` 集成 / `feature/{module}-{topic}` 开发；提交格式 `类型(模块): 说明`。
- **PR 门禁**：范围、依赖、DB/API 影响、验证结果、风险；至少一名他人评审，涉及数据库/公共后端/公共前端/全局文档时对应维护人必须评审；禁止直接推 `develop`。
- **后端规范**：Controller 不写 SQL/业务；Service 管状态机、数据范围、事务；Repository 只做参数化读写；DTO 与 Entity 分离；统一 `ApiResponse`/`PagedResult`；异常用 `BusinessException` 子类；跨表写必须显式事务 + 状态条件更新/行锁；SQL 列名逐列对照 V001，避开 Oracle 保留字。
- **前端规范**：统一 Axios 客户端、环境变量 base URL、Store 管登录态、集中枚举映射、每个页面处理加载/空/提交中/失败/403。
- **数据库规范**：大写下划线命名、identity 主键、`Y/N`、英文状态枚举、`TIMESTAMP(0)`、脚本化变更、已执行迁移不可原地改。
- **DoD**：后端需 Swagger 可见 + 1 正常 + 2 关键失败 HTTP 用例 + 401/403/404/409 验证 + 事务与参数化；前端需真实 API + 全状态处理 + 不硬编码字段。
- **决策基线**：D-001~D-015 全部 `ACCEPTED`（技术栈、Oracle 版本、identity、账号分离、13 表、报名关联 `HR_FILED`、发布占用预算并冻结、PRE/POST 时点、缺勤不自动拉黑、接口为推荐基线）。
