## 4. 通用接口契约需求

### 4.1 统一响应

所有JSON接口暂按以下结构消费，最终以冻结OpenAPI为准：

| 字段 | 类型 | 必填 | 前端用途 | 要求 |
| --- | --- | --- | --- | --- |
| `success` | boolean | 是 | 判断业务请求是否成功 | HTTP成功但业务失败时仍需有稳定判定方式 |
| `message` | string | 是 | 全局或操作结果提示 | 不得包含SQL、堆栈、连接信息等内部细节 |
| `data` | T/null | 是 | 页面数据 | 空结果使用约定的空对象、空数组或`null` |
| `errors` | array | 否 | 表单字段错误 | 每项至少包含`field`、`message`，建议提供稳定`code` |
| `traceId` | string | 是 | 联调、日志与故障定位 | 失败提示允许复制，不能暴露其他内部信息 |

### 4.2 分页、搜索与排序

| 项目 | 前端需求 | 当前口径 |
| --- | --- | --- |
| 页码 | `page`，从1开始 | 默认1 |
| 每页数量 | `pageSize` | 默认20；可选10、20、50 |
| 分页结果 | `items`、`page`、`pageSize`、`total` | 服务端分页 |
| 搜索 | 条件改变后回到第1页 | 空字符串不应被解释为有效过滤条件 |
| 排序 | 建议统一`sortBy`、`sortOrder=asc|desc` | 只允许后端白名单字段，避免任意SQL排序 |
| 日期范围 | 建议`startFrom`、`startTo`等显式边界名 | 使用ISO 8601；边界是否包含待确认 |
| 返回列表 | 恢复筛选、页码和滚动位置，再刷新可能变化的行 | 由前端路由状态管理，不要求接口保存页面状态 |

### 4.3 认证、权限与安全

- 受保护接口统一在401表示未登录或登录失效，在403表示已登录但无操作权限。
- 菜单和按钮隐藏仅改善体验，后端必须按角色、数据范围和业务状态重新校验。
- 员工本人、主管本部门等数据范围应由后端根据登录上下文过滤，不能信任前端提交的`empId`或`deptId`。
- 越权查询具体资源返回403还是404必须统一，避免通过差异推断资源是否存在。
- 写操作需返回稳定业务错误码；重复报名、重复证书、重复审批等冲突建议使用409。
- 登录凭证不得出现在URL、日志、页面截图或错误详情中。

### 4.4 时间、金额与空值

- 日期时间使用带时区的ISO 8601字符串；系统业务时区暂按`Asia/Shanghai`，需后端确认。
- 纯日期使用`YYYY-MM-DD`，金额和学时使用JSON number，不返回格式化字符串。
- 缺失可选值统一返回`null`，不混用空字符串、`0`和`"null"`。
- 剩余名额、剩余预算、实际学时和资格结果由后端计算并返回，前端不以多个原始字段拼装业务结论。

## 8. 写操作、错误与并发要求

| 操作 | 成功后前端行为 | 必须区分的失败 |
| --- | --- | --- |
| 登录 | 获取当前用户并进入原目标页或控制台 | 账号密码错误、账号停用、登录频率限制、服务异常 |
| 提交申请 | 进入我的申请并定位新记录 | 课程不可申请、重复待处理申请、员工离职、字段错误 |
| 主管通过/驳回 | 关闭确认层并刷新目标行 | 已被处理、越权部门、状态不允许、意见校验失败 |
| HR备案 | 刷新待备案列表和申请详情 | 未经主管通过、重复备案、越权、数据冲突 |
| 创建/取消报名 | 刷新课程资格和报名记录 | 未备案、满员、黑名单、重复报名、已开始、已签到 |
| 签到/缺勤/完成 | 刷新报名详情与统计 | 状态不允许、重复签到、时间不允许、学时不足、并发处理 |
| 生成证书 | 进入证书详情 | 培训未完成、测试门槛未满足、重复证书、编号冲突 |

未知结果场景（超时或连接断开）不得直接提示“失败并可立即重试”。前端需要通过详情或列表查询核对最终状态；后端应提供幂等机制或可安全查询的业务标识。

| --- | --- | --- |
| `RoleCode` | `EMPLOYEE`、`DEPT_MANAGER`、`HR`、`ADMIN` | 多角色、主角色和权限码模型 |

## 12. 评审建议顺序

1. 后端基础与认证负责人评审通用契约、认证、错误、分页和权限模型。
2. 讲师与课程负责人评审课程列表、详情、余量和资格字段。
3. 培训申请审批负责人评审申请、主管审批、HR备案及数据范围。

5. 成果评估负责人评审证书候选、生成、详情、状态和下载能力。
6. 项目负责人确认跨模块规则、P0范围、接口冻结日期和未决事项负责人。
