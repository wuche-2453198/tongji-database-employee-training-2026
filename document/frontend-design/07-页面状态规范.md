## 2. 设计目标

1. 让所有P0页面在正常、等待、无数据、失败、无权限和业务冲突情况下都有明确表现。
2. 区分“没有业务数据”和“搜索条件没有结果”，避免用户误以为数据丢失。
3. 区分页面加载、局部刷新和操作提交，避免一个操作锁死整个页面。
4. 让失败反馈说明发生了什么、为什么以及用户下一步可以做什么。
5. 为步骤9的Mock场景提供统一状态编号和验收依据。

## 3. 页面状态模型

### 3.1 页面级状态

| 状态编号 | 状态名称 | 触发条件 | 推荐载体 | 是否替换主要内容 |
| --- | --- | --- | --- | --- |
| PAGE-INIT | 初始 | 页面刚进入、尚未发起必要查询 | 默认结构/引导区 | 视页面而定 |
| PAGE-LOADING | 首次加载 | 页面无可复用内容且正在获取数据 | Skeleton/Loading | 是 |
| PAGE-READY | 正常有数据 | 必要数据成功返回且可展示 | 正常页面 | 否 |
| PAGE-EMPTY | 业务空数据 | 查询成功，但该用户/业务尚无任何记录 | Empty | 是 |
| PAGE-NO-RESULT | 搜索无结果 | 存在筛选条件，查询成功但结果为0 | Empty + 清空筛选 | 替换结果区 |
| PAGE-LOAD-ERROR | 加载失败 | 首次或必要查询失败 | Alert/Result + 重试 | 是或替换失败区 |
| PAGE-PARTIAL-ERROR | 局部失败 | 页面主体可用，但某个区块加载失败 | 区块Alert + 重试 | 否 |
| PAGE-FORBIDDEN | 无页面权限 | 已登录，但角色或数据范围不允许访问 | 403页 | 是 |
| PAGE-NOT-FOUND | 页面/资源不存在 | 路径或资源不存在 | 404/资源不存在 | 是 |
| PAGE-SESSION-EXPIRED | 登录过期 | 受保护请求返回未登录/会话失效 | 全局提示后登录页 | 是 |

### 3.2 操作级状态

| 状态编号 | 状态名称 | 触发条件 | 推荐载体 | 页面数据处理 |
| --- | --- | --- | --- | --- |
| ACTION-IDLE | 可操作 | 权限与业务条件满足 | 正常按钮/表单 | 不变 |
| ACTION-DISABLED | 不可操作 | 权限不足或业务状态不满足 | 禁用/隐藏 + 原因 | 不变 |
| ACTION-SUBMITTING | 提交中 | 写操作已经发出，结果未返回 | 按钮Loading/行Loading | 保留现有数据 |
| ACTION-SUCCESS | 提交成功 | 服务端确认操作成功 | Message + 局部刷新 | 使用服务端最新数据 |
| ACTION-VALIDATION | 校验失败 | 字段或参数不合法 | 字段错误 + 表单顶部摘要 | 保留用户输入 |
| ACTION-CONFLICT | 业务冲突 | 重复、满员、状态变化等 | Message/Alert + 刷新 | 获取最新数据 |
| ACTION-FORBIDDEN | 无操作权限 | 页面可访问但按钮无权限 | 隐藏/禁用或403反馈 | 不暴露敏感结果 |
| ACTION-SYSTEM-ERROR | 系统失败 | 服务器异常或未知错误 | Message/Alert + `traceId` | 不假定操作成功 |
| ACTION-UNKNOWN | 结果未知 | 超时、断网且无法判断写操作是否完成 | 警告 + 查询最新记录 | 禁止立即盲目重复提交 |

### 3.3 状态优先级

同一时刻出现多个条件时，按照以下优先级决定主界面：

```text
登录过期
→ 页面无权限
→ 页面或资源不存在
→ 首次加载
→ 必要数据加载失败
→ 业务空数据 / 搜索无结果
→ 正常有数据
```

操作提交、字段校验和局部失败作为当前页面的叠加状态，不应无理由替换整个页面。

## 4. 通用状态视觉规范

### 4.1 初始状态

- 列表页加载默认查询条件后立即发起查询，不显示“请点击查询”占位。
- 必须先选择上下文的页面可以显示引导，例如报名与签到页“请先选择课程”。
- 新增/提交表单展示默认值、只读上下文和必填标记。
- 详情页进入后直接加载资源，不显示上一页面传入的未经验证完整对象。
- 默认筛选条件必须可见，例如课程中心普通员工默认关注“已发布”。

### 4.2 加载中

| 场景 | 表现 | 禁止行为 |
| --- | --- | --- |
| 首次加载整页 | 使用与最终布局接近的骨架屏 | 使用虚假业务数据填充 |
| 表格查询/翻页 | 表格局部Loading，保留表头和搜索条件 | 清空整个页面或跳回顶部 |
| 详情局部刷新 | 对应信息区块Loading | 锁死无关操作区域 |
| 按钮提交 | 按钮显示“提交中/处理中”并禁用冲突操作 | 重复点击产生多次请求 |
| 行内操作 | 仅当前行进入Loading | 禁用整张表所有行 |

- 短请求也应保持状态连续，避免快速闪烁造成“按钮没有响应”的感觉。
- Loading结束后焦点位置保持合理，不自动跳到页面顶部。
- 加载失败时移除Loading，并显示可执行的恢复动作。

### 4.3 正常有数据

- 页面展示服务端返回的最新数据和状态。
- 空字段统一显示`—`，不显示`null`、`undefined`或接口原始枚举。
- 主要操作根据角色权限、数据范围和业务状态共同判断。
- 操作成功后刷新受影响对象及相关统计，禁止前端自行猜测聚合结果。

### 4.4 空数据与搜索无结果

| 类型 | 判断方式 | 标题示例 | 说明示例 | 主要动作 |
| --- | --- | --- | --- | --- |
| 业务空数据 | 没有筛选或使用默认筛选，数据总数为0 | 暂无培训申请 | 你还没有提交过培训申请 | 浏览课程 |
| 搜索无结果 | 存在非默认筛选，当前结果为0 | 未找到匹配结果 | 请调整关键词、状态或日期范围 | 清空筛选 |
| 权限范围内为空 | 查询成功，但当前角色范围无记录 | 暂无待审批申请 | 当前没有需要你处理的申请 | 返回首页 |
| 上下文未选择 | 页面需要先选课程等上下文 | 请先选择课程 | 选择课程后查看报名和签到记录 | 聚焦选择控件 |

- 空状态动作只显示当前用户有权限执行的入口。
- 空数据不能用加载失败或404替代。
- 搜索无结果时保留筛选条件，方便用户修改。

### 4.5 加载失败

```text
标题：数据加载失败
说明：暂时无法获取页面数据，请稍后重试。
辅助：问题编号：{traceId}（后端返回时显示）
操作：[重新加载] [返回上一页]
```

- 首次必要查询失败使用页面级反馈。
- 页面主体可用时，局部区块失败只替换该区块。
- 重试必须重新请求数据，不能只隐藏错误提示。
- 不展示数据库连接串、SQL、堆栈或内部异常详情。

## 5. HTTP与错误响应映射

最终以冻结接口为准，当前按照项目开发规范设计：

| HTTP状态 | 含义 | 页面处理 | 操作处理 | 用户反馈 |
| --- | --- | --- | --- | --- |
| 200/201 | 成功 | 展示或刷新数据 | 成功提示 | 使用返回的最新对象 |
| 400 | 参数或业务规则不满足 | 保持页面 | 映射字段错误或业务提示 | 修正后重试 |
| 401 | 未登录/登录过期 | 进入登录恢复流程 | 中止当前操作 | “登录状态已失效，请重新登录” |
| 403 | 无权限 | 页面级进入403 | 按钮级提示无权操作 | 不暴露越权数据 |
| 404 | 路径或资源不存在 | 404或资源不存在 | 关闭无效操作上下文 | 返回有权限列表页 |
| 409 | 数据冲突 | 保留页面并刷新对象 | 冲突提示 | 说明重复/状态变化/满员等原因 |
| 500 | 服务端异常 | 页面或区块失败 | 系统失败提示 | 提供重试及`traceId` |

### 5.1 统一响应字段使用

| 字段 | 前端用途 |
| --- | --- |
| `success` | 辅助判断业务成功，不替代HTTP状态处理 |
| `message` | 作为用户提示基础，但前端需避免直接显示不安全内容 |
| `errors[]` | 按`field`映射表单错误；无法映射时显示表单顶部摘要 |
| `traceId` | 在系统错误或联调问题中展示，便于后端定位 |
| `data` | 成功后的页面或业务数据 |

## 6. 表单与提交状态

### 6.1 提交前

- 用户输入保留在页面内，不因普通查询或局部刷新丢失。
- 提交前执行基础必填、格式、长度和范围校验。
- 第一个错误字段获得焦点，所有字段错误同时保留。
- 业务资格只做提示性预检查，最终以后端结果为准。

### 6.2 提交中

- 主按钮文案改为“提交中…”或具体动作“备案中…”。
- 禁用确认、取消及会导致冲突的同对象操作。
- 不允许连续点击产生重复申请、报名、签到或证书。
- 页面其他无关区域保持可读，但避免离开导致结果不明确。

### 6.3 提交成功

| 操作 | 成功文案 | 后续动作 |
| --- | --- | --- |
| 登录 | 登录成功 | 进入原目标页或控制台 |
| 提交申请 | 培训申请已提交 | 进入申请详情或我的申请 |
| 主管通过 | 申请已审批通过 | 刷新当前行及待办数量 |
| 主管驳回 | 申请已驳回 | 刷新当前行及待办数量 |
| HR备案 | 备案已完成 | 刷新当前行及待办数量 |
| 报名 | 报名成功 | 进入我的报名或报名详情 |
| 取消报名 | 报名已取消 | 刷新报名状态 |
| 签到 | 签到成功，实际学时已更新 | 刷新当前行及统计 |
| 标记缺勤 | 已标记为缺勤 | 刷新当前行，显示后续影响 |
| 完成培训 | 培训状态已更新为已完成 | 刷新当前行 |
| 生成证书 | 证书生成成功 | 进入证书详情或刷新列表 |

### 6.4 结果未知

写操作超时或断网时，不直接提示“失败并请重试”，因为服务端可能已经完成操作。

```text
标题：操作结果尚未确认
说明：网络中断，暂时无法确认操作是否完成。
操作：[查询最新状态] [返回列表]
```

查询最新状态后：

- 状态已变化：按成功结果展示。
- 状态未变化：允许用户重新提交。
- 仍无法查询：保留问题编号和操作上下文，提示稍后重试。

## 7. 权限与登录状态

### 7.1 未登录访问

- 记录原目标路径，进入`/login`。
- 登录成功后暂定回到原目标页面；若已无权限则进入403。
- 不把密码、Token或敏感参数放入回跳URL。

### 7.2 登录过期

```text
提示：登录状态已失效，请重新登录。
动作：清理无效登录态 → 进入登录页 → 登录后尝试回到原页面
```

- 取消正在进行的后续受保护请求。
- 不重复弹出多个过期提示。
- 未提交表单是否恢复待认证方案确认；当前不承诺持久化敏感表单内容。
- 回跳后必须重新加载服务端数据，不能沿用过期缓存决定权限。

### 7.3 页面无权限

- 已登录但路由角色不匹配：进入403。
- 已登录、角色匹配但数据不属于本人/部门：按后端结果进入403或资源不存在，口径待接口确认。
- 403页显示返回上一页和返回首页，不显示越权资源内容。

### 7.4 操作无权限

- 明确无权的按钮默认不展示。
- 权限可能动态变化或需要解释时，可以禁用并说明“当前角色无此操作权限”。
- 服务端返回403时立即撤销乐观反馈并刷新权限/数据。

## 10. 公共页面状态设计

### 10.1 登录页

| 状态 | 页面表现 | 文案/动作 |
| --- | --- | --- |

## 15. 提示文案规范

### 15.1 文案公式

```text
状态/结果 + 原因 + 可执行下一步
```

### 15.2 推荐文案

| 类型 | 推荐 | 避免 |
| --- | --- | --- |
| 空数据 | 暂无培训申请，你可以先浏览课程 | 暂无数据 |
| 无结果 | 未找到匹配课程，请调整筛选条件 | 无数据 |
| 加载失败 | 暂时无法获取课程，请重试 | 系统异常 |
| 字段错误 | 申请理由不能超过500字 | 参数错误 |
| 状态冲突 | 该申请已由其他人员处理，页面已刷新 | 操作失败 |
| 权限不足 | 当前角色没有备案权限 | 403 |
| 登录过期 | 登录状态已失效，请重新登录 | Token失效 |
| 系统错误 | 服务暂时不可用，请稍后重试。问题编号：… | 数据库连接失败/堆栈信息 |

### 15.3 Message持续时间

- 普通成功提示建议约3秒后消失。
- 警告和错误建议约5秒，重要错误同时留在页面内。
- 登录过期、危险确认和结果未知不得仅使用自动消失提示。
- 读屏用户必须能够获知动态反馈。

## 16. 焦点、键盘与可访问性

- 页面加载完成后不随意抢夺用户焦点。
- 打开弹窗后焦点进入标题或第一个可操作控件；关闭后回到触发按钮。
- 表单校验失败时焦点移动到第一个错误字段。
- 页面级失败后，“重新加载”是清晰可聚焦的主要动作。
- 状态标签必须包含文字，不能只通过颜色表达。
- Loading状态需要可读的状态名称，不只显示旋转图标。
- 禁用按钮无法说明原因时，旁边提供帮助文字；不要依赖禁用按钮自身Tooltip作为唯一说明。
- 动态成功、错误和冲突消息需要适当的可访问通知区域。

## 17. 数据刷新与缓存规则

| 场景 | 刷新策略 |
| --- | --- |
| 返回列表 | 恢复筛选、分页和滚动位置，再刷新可能变化的目标行 |
| 审批/备案成功 | 刷新当前行、待办总数和详情状态 |
| 报名/取消成功 | 刷新课程余量、我的报名和课程详情资格 |
| 签到/缺勤/完成 | 刷新报名记录、签到记录和后端统计 |
| 生成证书 | 刷新候选列表、证书列表和员工证书状态 |
| 角色权限变化 | 重新获取当前用户与权限，重新生成菜单 |
| 登录后回跳 | 重新加载页面，不使用过期权限和业务缓存 |

前端缓存只用于提升体验，不能覆盖后端最新业务状态。

## 19. 页面状态验收清单

### 19.1 通用状态

- [ ] 首次加载、局部刷新和按钮提交有不同Loading表现。
- [ ] 业务空数据与搜索无结果使用不同文案和恢复动作。
- [ ] 加载失败提供重试，必要时展示`traceId`。
- [ ] 表单校验失败保留用户输入并定位错误字段。
- [ ] 写操作结果未知时先查询最新状态，不盲目重复提交。

### 19.2 权限与安全

- [ ] 未登录、登录过期、页面无权限和操作无权限可以区分。
- [ ] 403/404不暴露越权或敏感资源信息。
- [ ] 页面不会展示数据库、SQL、堆栈和连接信息。
- [ ] 登录过期只触发一次全局恢复流程。

### 19.3 业务冲突

- [ ] 重复申请、重复报名、满员和黑名单有限定文案。
- [ ] 重复审批、备案、签到和证书会刷新最新状态。
- [ ] 课程关闭、课程开始、学时不足和证书资格不足有下一步。
- [ ] 冲突处理依赖业务码或HTTP状态，不依赖中文字符串匹配。

### 19.4 P0覆盖

- [ ] 17个P0及辅助页面均在状态矩阵中覆盖。
- [ ] 每个列表页覆盖正常、空数据、无结果和失败。
- [ ] 每个表单/状态流转页覆盖提交、成功、校验和冲突。
- [ ] 每个受保护页面覆盖无权限和登录过期。
