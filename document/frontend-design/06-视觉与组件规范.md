## 2. 设计目标与原则

### 2.1 设计目标

1. 让员工、主管、HR 和管理员快速识别自己的入口、待办和下一步操作。
2. 让申请、审批、备案、报名、签到和证书等状态在不同页面保持一致。
3. 降低后台表格、表单和状态流转操作的理解成本与误操作风险。
4. 形成可以直接交给前端开发人员实现的视觉和组件约束。
5. 在不依赖精细插画和复杂动画的情况下，保持专业、稳定和易读。

### 2.2 设计原则

- 信息优先：视觉层级服务于业务信息，不使用无业务含义的大面积装饰。
- 一致优先：相同状态、按钮和表单控件在所有页面保持同一表达。
- 操作可解释：禁用、失败和冲突必须说明原因，不能只改变颜色。
- 后端为准：前端不自行推导关键业务状态、权限、统计或学时结果。
- 渐进披露：列表展示摘要，详情展示完整信息，危险操作使用确认反馈。
- 无障碍：文本与背景保持足够对比，键盘焦点清晰，状态不只依赖颜色。

## 3. UI 组件库基线

### 3.1 基线决策

本项目视觉与公共组件以 Element Plus 为基础，理由如下：

- 与已冻结的 Vue 3、TypeScript、Vite 技术路线一致。
- 覆盖表单、表格、分页、标签、对话框、抽屉、描述列表、时间线和反馈组件。
- 适合企业后台的高密度查询、数据维护和状态流转场景。
- 可以通过主题变量统一品牌色、文字、边框、圆角和组件状态。

官方资料：

- [Element Plus 安装与兼容性](https://element-plus.org/en-US/guide/installation)
- [Element Plus 快速开始](https://element-plus.org/en-US/guide/quickstart.html)
- [Element Plus 组件总览](https://element-plus.org/en-US/component/overview.html)

### 3.2 当前确认与延后事项

| 项目 | 当前结论 | 状态 |

## 4. 设计令牌总览

设计稿、组件规范和未来代码应共享同一套语义令牌。禁止在不同页面随意新增相近颜色、间距和圆角。

### 4.1 命名原则

```text
颜色：color-{用途}-{层级}
文字：text-{层级}
间距：space-{数值}
圆角：radius-{层级}
阴影：shadow-{层级}
组件：component-{组件}-{属性}
```

令牌名表达用途，不使用 `blue-1`、`gray-3` 等仅表达颜色外观的业务变量。

| `color-primary-active` | `#1E40AF` | 主要操作按下态 |
| `color-primary-soft` | `#EFF6FF` | 低强调选中背景、信息标签背景 |

| `color-surface` | `#FFFFFF` | 表格、表单、弹窗等主要表面 |
| `color-surface-subtle` | `#F1F5F9` | 表头、禁用、分组背景 |
| `color-border` | `#E2E8F0` | 默认边框和分隔线 |
| `color-border-strong` | `#CBD5E1` | 强调分隔、悬停边框 |
| `color-focus` | `#2563EB` | 键盘焦点轮廓 |

### 5.2 文字色

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `text-primary` | `#0F172A` | 页面标题、正文和关键数据 |

| `text-placeholder` | `#64748B` | 输入提示、空值提示 |

| `text-link` | `#1D4ED8` | 文本链接 |

### 5.3 语义色

| 语义 | 主色 | 浅背景 | 深色文字 | 用途 |
| --- | --- | --- | --- | --- |
| 成功 | `#15803D` | `#F0FDF4` | `#166534` | 完成、通过、已发布、保存成功 |
| 警告 | `#B45309` | `#FFFBEB` | `#92400E` | 待处理、即将过期、需注意 |
| 错误 | `#B91C1C` | `#FEF2F2` | `#991B1B` | 驳回、缺勤、失败、危险操作 |
| 信息 | `#2563EB` | `#EFF6FF` | `#1D4ED8` | 已报名、已签到、普通信息 |
| 中性 | `#64748B` | `#F1F5F9` | `#475569` | 草稿、关闭、取消、离职 |

### 5.4 色彩使用规则

- 一个页面同时只保留一个高强调主操作。
- 红色只用于失败、删除、驳回、缺勤等危险或负向语义。
- 状态标签必须同时显示中文状态文本，不能只用颜色区分。
- 大面积背景使用页面背景或白色表面，语义色只用于小范围反馈和状态。
- 链接、按钮、标签、图标在不同页面使用相同语义色映射。
- 图表统计属于 P2，后续不得直接把状态标签色机械套用到图表系列色。

## 6. 业务状态展示规范

### 6.1 状态标签基础规则

- 状态使用“浅背景 + 深色文字 + 中文文本”的标签形式。
- 标签高度建议 24px，水平内边距 8px，圆角 4px。
- 列表中同一列的标签宽度不强制相同，但文本不得换行。
- 详情页重要状态可使用更大的状态标签，但不改变语义颜色。
- 未知状态显示“未知状态”，使用中性标签并记录联调问题。

### 6.2 状态映射

| 业务 | 接口状态 | 中文标签 | 语义 | 说明 |
| --- | --- | --- | --- | --- |
| 员工 | `ACTIVE` | 在职 | 成功 | 可以参与正常业务 |
| 员工 | `RESIGNED` | 离职 | 中性 | 禁止新申请和报名 |
| 课程 | `DRAFT` | 草稿 | 中性 | 仅管理员可维护 |
| 课程 | `PUBLISHED` | 已发布 | 成功 | 可申请和报名 |
| 课程 | `CLOSED` | 已关闭 | 中性 | 禁止新申请和报名 |
| 申请 | `PENDING` | 待审批 | 警告 | 等待部门主管处理 |
| 申请 | `DEPT_APPROVED` | 主管通过 | 信息 | 等待 HR 备案 |
| 申请 | `DEPT_REJECTED` | 主管驳回 | 错误 | 流程结束 |
| 申请 | `HR_FILED` | HR 已备案 | 成功 | 暂定可进入报名 |
| 报名 | `REGISTERED` | 已报名 | 信息 | 等待签到或取消 |
| 报名 | `SIGNED_IN` | 已签到 | 信息 | 等待完成处理 |
| 报名 | `ABSENT` | 缺勤 | 错误 | 负向终态 |
| 报名 | `COMPLETED` | 已完成 | 成功 | 可进入成果流程 |
| 报名 | `CANCELED` | 已取消 | 中性 | 终态 |
| 黑名单 | `ACTIVE` | 生效中 | 错误 | 禁止报名 |
| 黑名单 | `RELEASED` | 已解除 | 中性 | 历史记录 |
| 证书 | 暂定派生状态 | 有效 | 成功 | 是否由接口返回待确认 |
| 证书 | 暂定派生状态 | 即将过期 | 警告 | 提醒时间窗口待确认 |
| 证书 | 暂定派生状态 | 已过期 | 错误/中性 | 业务口径待确认 |

### 6.3 流程进度表达

- 申请流程采用“员工提交 → 主管审批 → HR 备案”三节点时间线。
- 报名流程采用“报名成功 → 签到 → 培训完成”三节点时间线。
- 已完成节点使用成功语义，当前节点使用主色，未开始节点使用中性。
- 驳回、缺勤等异常终态在对应节点显示错误语义，并停止后续节点。

## 7. 字体规范

### 7.1 字体族

不引入网络字体，优先使用操作系统中文字体：

```text
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
"Microsoft YaHei", "Noto Sans CJK SC", Arial, sans-serif
```

### 7.2 字号与层级

| 层级 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 24/32px | 600 | 页面名称、登录标题 |
| 区块标题 | 20/28px | 600 | 大区块或详情主要标题 |
| 组件标题 | 16/24px | 600 | 卡片、弹窗、抽屉标题 |
| 正文 | 14/22px | 400 | 表格、表单、正文 |
| 强调正文 | 14/22px | 500 | 关键字段、操作入口 |
| 辅助文字 | 13/20px | 400 | 说明、时间、次要信息 |
| 注释文字 | 12/18px | 400 | 字数、帮助文本、追踪信息 |

使用规则：

- 正文不得小于 12px。
- 同一页面最多出现三级清晰标题层级。
- 不使用全大写英文作为中文界面标题。
- 金额、分数、学时和数量使用等宽数字特性（开发阶段实现）。

## 8. 间距、栅格与尺寸

### 8.1 间距系统

以 4px 为基础单位：

| 令牌 | 数值 | 典型用途 |
| --- | --- | --- |
| `space-1` | 4px | 图标与文字、紧密元素 |
| `space-2` | 8px | 按钮组、标签间距 |
| `space-3` | 12px | 表单帮助文本、紧凑区块 |
| `space-4` | 16px | 表单项、卡片内部、列表行操作 |
| `space-5` | 20px | 中型区块内部 |
| `space-6` | 24px | 页面内区块和页面边距 |
| `space-8` | 32px | 大区块分隔 |
| `space-10` | 40px | 登录页、空状态区域 |
| `space-12` | 48px | 页面大段落 |

禁止使用 5px、7px、18px 等不在间距体系中的随意值，确有组件对齐需要时必须记录原因。

### 8.2 页面布局尺寸

| 项目 | 建议尺寸 | 说明 |
| --- | --- | --- |
| 顶部栏高度 | 56px | 品牌、待办、个人菜单 |
| 侧边栏宽度 | 224px | 展开状态 |
| 侧边栏折叠宽度 | 64px | 是否开放折叠待高保真评审 |
| 页面水平边距 | 24px | 1200px 以上桌面视口 |
| 紧凑页面边距 | 16px | 1024～1199px |
| 区块间距 | 24px | 搜索、表格、详情区块之间 |
| 表单最大内容宽度 | 880px | 新增/编辑页面，避免字段过宽 |
| 详情正文最大宽度 | 1200px | 超宽视口不无限拉伸 |
| 最小支持宽度 | 1024px | 当前桌面后台基线 |

### 8.3 栅格规则

- 页面采用 24 栅格思路，与 Element Plus 栅格能力保持一致。
- 搜索区默认每行 3～4 个条件，标签和输入框作为一个整体。
- 两列表单每列占 12 栅格；长文本、日期范围、上传类字段占 24 栅格。
- 详情页两栏信息在 1024px 下可以退化为单栏。
- 表格优先保证“名称、状态、关键时间、操作”可见，次要字段允许隐藏或进入详情。

## 9. 圆角、边框与阴影

| 令牌 | 数值 | 用途 |
| --- | --- | --- |
| `radius-sm` | 4px | 状态标签、小控件 |
| `radius-md` | 6px | 输入框、按钮、表格容器 |
| `radius-lg` | 8px | 卡片、搜索区、弹窗 |
| `radius-xl` | 12px | 登录面板等少量重点表面 |
| `border-default` | 1px solid `#E2E8F0` | 输入、表格分隔、容器 |
| `shadow-sm` | `0 1px 2px rgba(15, 23, 42, 0.08)` | 下拉菜单、悬浮层 |
| `shadow-md` | `0 8px 24px rgba(15, 23, 42, 0.12)` | 弹窗、抽屉 |

使用规则：

- 页面主要分区优先使用留白和细边框，不为每个区域都添加阴影。
- 卡片不嵌套卡片；详情内部使用分组标题和分隔线。
- 表格默认不使用纵向网格线，必要的复杂财务表格另行评审。
- 不使用大圆角、强发光、玻璃拟态等与企业后台不一致的效果。

## 10. 图标规范

- 图标用于帮助识别，不替代关键操作文字。
- 普通图标建议 16px，菜单图标 18px，空状态图标 48～64px。
- 同一动作只使用一个固定图标，例如查看、编辑、删除、返回、搜索。
- 行操作优先显示文字按钮；空间不足时才使用带 Tooltip 的图标按钮。
- 危险图标与危险文案同时使用，不依赖红色或图标单独传达含义。
- 不混用多套线性、填充或彩色图标风格。

## 11. 按钮规范

### 11.1 按钮层级

| 类型 | 使用场景 | 示例 |
| --- | --- | --- |
| 主要按钮 | 页面或弹窗当前唯一主要动作 | 提交申请、确认签到、生成证书 |
| 默认按钮 | 普通次要动作 | 查询、重置、取消、返回 |
| 文字按钮 | 表格行内低风险操作 | 详情、查看课程 |
| 危险按钮 | 驳回、缺勤、解除等高风险动作 | 驳回、标记缺勤 |
| 禁用按钮 | 权限或业务状态不满足 | 课程已满、培训未完成 |

### 11.2 尺寸与排列

- 普通按钮高度建议 32px，登录和重要表单主按钮可使用 40px。
- 同组按钮间距 8px。
- 页面级主要按钮放在标题区域右侧；表单提交按钮放在表单末尾右侧。
- 弹窗按钮顺序为“取消在左、确认在右”。
- 表格行内最多直接展示 3 个操作，更多操作进入“更多”菜单。
- 同一按钮提交中显示加载状态并防止重复触发。

### 11.3 文案规则

- 使用“动词 + 对象”：提交申请、完成备案、取消报名、生成证书。
- 避免“确定”“处理”等无法说明结果的模糊文案。
- 禁用按钮必须配合 Tooltip、附近提示或状态文本说明原因。
- 危险操作确认文案必须说明对象和结果，例如“确认将张三标记为缺勤？”

## 12. 搜索区规范

### 12.1 结构

```text
搜索条件 1    搜索条件 2    搜索条件 3    [查询] [重置]
展开后条件 4  展开后条件 5  日期范围      [收起]
```

### 12.2 使用规则

- 搜索区位于页面标题下、表格上方。
- 首行优先保留最常用的 3～4 个条件。
- 超过 4 个条件时提供“展开/收起”，但 P0 页面尽量避免过多条件。
- “查询”是搜索区主要操作，“重置”恢复默认条件并重新查询。
- 文本输入按 Enter 可以触发查询；组合输入时不得误提交其他表单。
- 日期范围必须显示开始和结束含义，后端时区和边界待接口确认。
- 下拉选项显示中文，提交值使用统一英文枚举。

## 13. 表格规范

### 13.1 基础样式

| 项目 | 规范 |
| --- | --- |
| 表头 | 14px/500，浅中性背景，高度约 44px |
| 数据行 | 高度约 48px，可因多行摘要增高 |
| 文本对齐 | 普通文本左对齐，数字右对齐，状态和短码可居中 |
| 空值 | 使用 `—`，不显示 `null`、`undefined` 或空字符串 |
| 长文本 | 单行省略，Tooltip 或详情查看完整内容 |
| 固定列 | 关键标识可固定左侧，操作列可固定右侧 |
| 选中 | 仅批量操作存在时使用复选框；P0 审批不启用批量 |

### 13.2 列顺序

推荐顺序：

```text
业务标识 → 主要名称 → 关联对象 → 关键时间 → 状态 → 结果 → 操作
```

例如主管审批：

```text
申请编号 → 员工 → 部门 → 课程 → 申请日期 → 理由摘要 → 状态 → 操作
```

### 13.3 行操作

- “详情”始终放在行操作第一位。
- 状态流转操作按正向在前、负向在后排列，例如“通过、驳回”。
- 危险操作不与查看操作使用相同视觉层级。
- 操作成功后刷新受影响行和后端统计，不在前端自行修改聚合值。
- 409 状态冲突时刷新当前行并说明“记录已由其他人处理”。

## 14. 分页规范

- 位于表格右下方，表格与分页间距 16px。
- 桌面端建议显示总数、每页条数、上一页、页码、下一页。
- 默认 `page=1`、`pageSize=20`，最终以冻结接口为准。
- 推荐每页选项为 10、20、50；超大列表是否支持 100 待性能验证。
- 修改搜索条件后回到第 1 页；仅切换详情返回时恢复原页码。
- 当前页删除最后一条数据后，重新判断合法页码。

官方组件参考：[Element Plus Pagination](https://element-plus.org/en-US/component/pagination)

## 15. 表单规范

### 15.1 布局

- 登录表单使用顶部标签的单列布局。
- 新增、编辑业务表单优先使用两列布局，标签宽度统一为 104～120px。
- 申请理由、审批意见、备注等长文本字段独占整行。
- 只读关联信息使用描述列表或只读文本，不伪装成可编辑输入框。
- 表单操作区与字段区间隔 24px，按钮靠右排列。

### 15.2 字段状态

| 状态 | 表现 |
| --- | --- |
| 默认 | 清晰标签、边框和占位提示 |
| 悬停 | 边框轻微增强 |
| 聚焦 | 主色边框和可见焦点轮廓 |
| 已填写 | 正常文字，不额外使用成功绿色 |
| 错误 | 错误边框、字段下方错误文案、聚焦第一个错误 |
| 禁用 | 中性背景、禁用文字、不可聚焦 |
| 只读 | 无编辑控件外观，使用文本或描述列表 |
| 加载 | 相关控件禁用并显示局部加载 |

### 15.3 校验规则

- 必填字段在标签后显示 `*`，并在错误时提供明确原因。
- 不仅依赖占位文字表达字段名称或格式。
- 客户端校验提供即时反馈，最终业务校验以后端为准。
- 服务端字段错误映射到对应字段；无法映射的错误显示在表单顶部。
- 字数限制同时显示当前字数和最大字数，例如 `120 / 500`。
- 日期、分数、星级、容量和预算显示合法范围，禁止无提示截断。
- 离开未保存表单时提示是否放弃修改。

官方组件参考：[Element Plus Form](https://element-plus.org/en-US/component/form)

## 16. 弹窗与抽屉规范

### 16.1 使用边界

| 载体 | 适用场景 | 不适用场景 |
| --- | --- | --- |
| 对话框 | 审批、备案、取消、缺勤、完成、生成证书等短流程 | 多步骤、需要深链接的完整详情 |
| 抽屉 | 从列表快速查看中等复杂详情或较长辅助表单 | 必须独立分享、刷新恢复的核心页面 |
| 独立页面 | 申请详情、报名详情、证书详情、复杂新增编辑 | 简单确认操作 |

Element Plus 将 Dialog 用于保留当前页面上下文的弹层；Drawer 更适合内容较多的临时区域。本项目仍以业务复杂度和是否需要独立路由作为最终判断依据：[Dialog](https://element-plus.org/en-US/component/dialog)、[Drawer](https://element-plus.org/en-US/component/drawer)。

### 16.2 对话框规范

- 简单确认宽度建议 440～480px，表单弹窗建议 560～640px。
- 标题明确业务动作，如“审批驳回”“生成证书”。
- 正文首屏展示操作对象和当前状态。
- 危险操作说明不可逆或联动影响。
- 点击遮罩、关闭按钮和取消按钮均应执行相同的未保存检查。
- 提交中不允许关闭或重复提交，除非明确支持安全取消。

### 16.3 抽屉规范

- 默认从右侧打开，宽度建议 560～720px 或视口的 40%～50%。
- 标题固定，正文可以滚动，操作区固定在底部。
- 长详情按照“基本信息、流程记录、相关结果”分组。
- 抽屉关闭后列表筛选和滚动位置保持不变。

## 17. 描述列表与流程时间线

### 17.1 描述列表

- 用于课程详情、申请详情、报名详情和证书运营信息。
- 标签使用次要文字色，值使用主要文字色。
- 桌面端通常两列，窄屏退化为一列。
- 重要状态不混入普通文本，使用状态标签展示。
- 空值统一显示 `—`。

### 17.2 时间线

- 申请流程节点：提交、主管审批、HR 备案。
- 报名流程节点：报名、签到、完成或异常终止。
- 每个节点包含动作名称、处理人、时间和意见摘要。
- 当前节点突出，未来节点弱化，驳回/缺勤节点使用错误语义。
- 时间线只是展示，不允许通过点击节点直接修改状态。

## 18. 消息与反馈规范

### 18.1 反馈层级

| 类型 | 载体 | 使用场景 | 持续方式 |
| --- | --- | --- | --- |
| 即时成功 | Message | 保存、审批、备案、签到成功 | 自动消失，可被读屏读取 |
| 即时错误 | Message + 页面错误 | 一次性操作失败 | 简短提示，详细原因留在页面 |
| 重要确认 | MessageBox/Dialog | 驳回、缺勤、取消报名、生成证书 | 用户明确确认 |
| 页面级警告 | Alert | 课程已关闭、资格不足、部分数据异常 | 持续显示直到状态变化 |
| 系统通知 | Notification | 非当前操作产生的异步通知（暂定） | 不在 P0 强制实现 |

### 18.2 文案结构

推荐格式：

```text
发生了什么 + 为什么 + 用户可以怎么做
```

示例：

- “报名失败：课程名额已满，请选择其他课程。”
- “审批未提交：该申请已由其他主管处理，页面已刷新。”
- “证书生成失败：该员工尚未完成培训。”
- “加载失败，请重试。问题编号：{traceId}。”

禁止使用：

- “操作失败”而没有原因或下一步。
- 直接展示数据库错误、堆栈、SQL 或连接信息。
- 将后端英文枚举直接展示给用户。

## 19. 加载、空数据与异常状态组件

| 页面状态 | 推荐组件 | 规范 |
| --- | --- | --- |
| 首次加载 | Skeleton/Loading | 保留页面结构，不显示伪造数据 |
| 表格刷新 | 表格局部 Loading | 不清空已有内容，避免页面跳动 |
| 空数据 | Empty | 说明无数据，并提供有权限的下一步 |
| 搜索无结果 | Empty | 显示当前条件无结果，提供“清空筛选” |
| 加载失败 | Alert/Result | 显示重试入口和必要的 `traceId` |
| 无权限 | Result/403 页 | 不暴露越权资源内容 |
| 资源不存在 | Result/404 页 | 提供返回来源列表或首页 |
| 提交中 | 按钮 Loading | 禁止重复提交，保留表单内容 |
| 状态冲突 | Alert/Message | 刷新最新状态，说明记录已变化 |

详细页面状态将在步骤 8 单独形成完整规范；本节只定义组件视觉和载体。

## 23. 可访问性规范

- 正文、按钮和关键状态保持足够的颜色对比度。
- 键盘访问时所有可操作控件必须有清晰焦点轮廓。
- 输入框必须有可见标签，不能仅依赖 placeholder。
- 图标按钮必须有可读名称或 Tooltip。
- 表单错误与具体字段关联，并把焦点移到第一个错误字段。
- 弹窗打开后焦点进入弹窗，关闭后回到触发按钮。
- 状态不能只依赖颜色，必须同时有文字或图标。
- 表格列头明确，分页和排序控件支持键盘操作。
- 动画只用于说明状态变化，尊重“减少动态效果”设置；当前不设计装饰动画。

## 24. 内容与文案规范

- 页面标题使用用户任务名称，例如“主管审批”，不使用数据库表名。
- 中文状态统一使用本规范中的映射，不在页面自行创造近义词。
- 日期列表默认 `YYYY-MM-DD`，含时间时使用 `YYYY-MM-DD HH:mm`；最终时区由接口规范确认。
- 金额显示人民币符号与两位小数，预算口径以后端为准。
- 学时最多保留一位小数，分数精度以后端字段为准。
- 人名、课程名和部门名超长时省略，详情中显示完整内容。
- 确认文案包含操作对象，成功文案包含操作结果。
- 不使用“亲”“哦”等口语化表达，保持清晰、礼貌和专业。

## 25. 高保真与开发交付要求

进入高保真和正式开发前，需要完成：

1. 在设计工具中建立颜色、文字、间距、圆角和阴影变量。
2. 建立按钮、输入、选择、状态标签、表格、分页、弹窗和页面状态组件。
3. 用组件实例而不是复制图层绘制 P0 页面。
4. 对照 Element Plus 能力判断直接使用、主题覆盖或业务封装。
5. 主题覆盖必须集中管理，不在页面内散落样式。
6. 创建工程时锁定 Element Plus、图标库和相关自动导入插件版本。
7. 视觉还原验收时重点检查字体、间距、状态色、按钮层级和表格密度。
