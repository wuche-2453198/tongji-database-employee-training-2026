## 3. 当前范围说明

### 3.1 已确认的技术与系统边界

- 前端技术路线为 Vue 3、TypeScript、Vite、Composition API、`<script setup>`、Vue Router、Pinia。
- 系统形态为 B/S 架构下的前后端分离后台管理 SPA。
- 前端未来只通过 HTTP API 调用 C# ASP.NET Core Web API，不直接连接 Oracle。
- 接口未冻结期间使用 Mock 数据支持设计和交互验证；Mock 字段不等于最终 API 字段。
- 当前阶段不创建正式前端工程、不安装依赖、不编写 Vue 页面、路由、状态管理和接口调用代码。
- 权限设计用于菜单、页面和按钮的展示体验；最终鉴权必须由后端执行。

### 3.2 已确认的用户角色

| 角色 | 核心职责 | 说明 |
| --- | --- | --- |
| 员工 | 浏览课程、提交申请、报名、查看培训结果、评分、查看证书 | 基础业务角色 |
| 部门主管 | 完成员工能力，并审批本部门培训申请 | 是否自动拥有全部员工能力暂定按“多角色权限并集”处理 |
| HR | 备案、培训运营、签到、评分复核、测试成绩、证书管理 | 是否同时拥有员工能力暂定按实际账号角色并集处理 |
| 管理员 | 维护员工、部门、讲师、课程、黑名单等基础数据 | 可参与签到；是否拥有全部 HR 操作待确认 |

## 5. 业务状态与展示口径

接口值优先采用开发规范中的英文枚举，中文仅用于界面展示；数据库设计原稿中的中文状态视为待后端统一映射。

| 业务 | 接口暂定值 | 中文展示 | 确认状态 |
| --- | --- | --- | --- |
| 员工 | `ACTIVE`、`RESIGNED` | 在职、离职 | 已确认 |
| 课程 | `DRAFT`、`PUBLISHED`、`CLOSED` | 草稿、已发布、已关闭 | 已确认 |
| 申请 | `PENDING`、`DEPT_APPROVED`、`DEPT_REJECTED`、`HR_FILED` | 待审批、主管通过、主管驳回、HR 已备案 | 已确认 |

| 测试类型 | `PRE`、`POST` | 训前、训后 | 已确认 |
| 是否值 | `Y`、`N` | 是、否 | 已确认 |

## 6. 页面通用体验需求

所有 P0 页面在后续阶段设计时至少覆盖：

- 初始、加载中、正常有数据、空数据、搜索无结果、加载失败。
- 提交中、提交成功、表单校验失败。
- 无权限、登录过期。
- 业务冲突，例如重复申请、重复报名、课程已满、课程已关闭、状态不允许操作。
- 列表查询暂定采用服务端分页，默认 `page=1`、`pageSize=20`，最终以冻结接口为准。
- 错误反馈使用后端统一 `message`，字段错误读取 `errors`，必要时显示 `traceId` 供联调定位。
