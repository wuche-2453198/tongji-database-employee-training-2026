## 2. 背景与目标

整合基线的前端业务页面长期停留在两类状态：报名、证书、评分、测试等仍为 Mock 验收，课程、申请、审批、备案等为「已适配、待后端」，真实 HTTP 契约缺失导致无法在真实环境运行验收。本次后端各业务模块的 Controller/DTO/Repository 已陆续合入，前端需要完成三件事：

1. 把前端业务页面从 Mock/阻塞适配器切换到真实后端 HTTP 契约；
2. 补齐后端缺失的列表、统计等接口；
3. 联调并修复合并后暴露的前后端数据口径、路由参数、筛选交互等级联缺陷。

## 4. 级联调试问题与修复

### 4.1 主管审批「清空筛选」按钮冗余且失效

- **现象**：主管审批页在筛选无结果时出现两个「清空筛选」按钮，其中一个点击无任何效果。
- **根因**：公共组件 `PageState.vue` 的 `no-result` 状态自带一个默认主按钮（文案「清空筛选」），而视图又额外传入 `secondary-label="清空筛选"` 并绑定 `@secondary`，造成重复；同时主按钮没有绑定 `@primary` 处理函数，点击无效。
- **修复**：移除冗余的 `secondary-label`/`@secondary`，只保留一个主按钮并绑定 `@primary`，重置员工/课程/状态/日期并回到第 1 页重新查询。
- **涉及文件**：`src/frontend/src/views/approvals/DepartmentApprovalView.vue`、`src/frontend/src/views/certificates/CertificateManagementView.vue`。

### 4.2 控制台卡片数值与跳转列表口径不符

- **现象**：控制台卡片显示写死的「待审批申请 5 / 本周已处理 12 / 逾期申请 2」，点击跳转到主管审批列表却是空的。
- **根因**：三点叠加——① `roleStats` 中卡片数值为硬编码，无真实统计来源；② 卡片跳转链接未携带 `?status=` 参数；③ `DepartmentApprovalView` 只 `onMounted(load)`，从未读取 `route.query`，路由参数被忽略。
- **修复**：① 后端新增 `GET /api/dashboard/stats`，按当前角色返回统计（主管按本部门、HR/管理员按全局，周口径以 `TRUNC(SYSDATE,'IW')` 为 ISO 周起点）；② `DashboardView` 改为从 `statsData` 实时取值，卡片 `to` 携带 `?status=`；③ `DepartmentApprovalView` 增加 `applyRouteQuery()`，从 `route.query` 初始化筛选条件。
- **涉及文件**：后端 `DashboardController`、`DashboardService`、`DashboardRepository`、`Program.cs`；前端 `domains/dashboard/`、`services/dashboard.ts`、`services/http/dashboard-http.ts`、`views/dashboard/DashboardView.vue`、`views/approvals/DepartmentApprovalView.vue`。

### 4.3 HR 证书管理页「服务暂不可用」

- **现象**：`/operations/certificates` 打开即报「数据加载失败：服务暂不可用」。
- **根因**：后端缺少证书列表/候选接口；前端 `certificate-http.ts` 的 `listManage`/`listCandidates` 显式抛出 `HTTP_CONTRACT_NOT_FROZEN`，统一错误链将其映射为「服务暂不可用」。
- **修复**：后端新增 `GET /api/certificates`（分页列表，`ORDER BY ISSUE_DATE DESC`，支持员工/课程/日期筛选）与 `GET /api/certificates/candidates`（`STATUS='COMPLETED'` 且 `NOT EXISTS` 已生成证书，联表员工/部门/课程，`ORDER BY COMPLETED_AT DESC`）；前端实现 `listManage`/`listCandidates` 的 HTTP 适配与 DTO 映射，移除阻塞抛错。
- **涉及文件**：后端 `CertificatesController`、`CertificateRepository`、`CertificateService`、`CertificateQueryDto`、`CertificateCandidate`、`TrainingCertificate`；前端 `services/http/certificate-http.ts`、`api/mappers/certificate.ts`、`api/transport.ts`、`views/certificates/CertificateManagementView.vue`。

### 4.4 其它联调修正

除上述三个核心缺陷外，本次联调还一并修正了若干此前标记为「已适配、待后端」或「Mock 验收」的能力：

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 课程详情名额缺失 | `CourseResponse` 未返回报名/剩余名额字段 | 后端补齐 `RegisteredCount`/`RemainingSeats` 并回填 |
| 评分/测试列表加载失败 | 后端接口与前端 HTTP 适配器均未就绪 | 补齐后端列表接口，前端实现 HTTP 适配 |
| 审批/备案筛选参数未生效 | `TrainingRequestQueryDto` 缺少员工名/课程名/部门/日期范围字段 | 后端补齐查询字段，前端按字段发送 |
| 空值字段显示异常 | 部分实体字段可空，前端未统一降级显示 | 前端视图统一以 `—` 降级展示空值 |
| `/requests/undefined` 路由错误 | 详情跳转缺少有效 id | 修正详情跳转与路由参数传递 |

## 6. 验证方式

- **后端**：`dotnet run --project src/backend/TrainingManagement.Api`（`ASPNETCORE_URLS=http://localhost:5156`），健康检查 `GET http://localhost:5156/api/health` 返回 200。
- **前端**：`pnpm --prefix src/frontend run dev:local`（`vite --mode devlocal`，即 `VITE_USE_MOCK=false` 走真实 HTTP），访问 `http://localhost:5173/` 返回 200。
- **页面验收点**：
  - 主管审批 `/approvals/department`：单「清空筛选」按钮生效，重置日期/状态/关键词并重新查询；
  - 控制台 `/dashboard`：卡片数值来自 `/api/dashboard/stats`，跳转链接带 `?status=` 且列表按该参数初始化筛选；
  - 证书管理 `/operations/certificates`：候选与已生成列表正常加载，不再报「服务暂不可用」。

## 7. 残余风险与后续

- 六个功能域当前为 `HTTP_ADAPTED`，尚未在四角色真实账号下完成 200/401/403/404/409/500 及数据范围（员工本人、主管本部门、HR 授权范围）的端到端验收，不能标记为 `INTEGRATION_DONE`。
- 报名、签到模块仍为 Mock 验收，其后端契约待苏黄罡方案合入后按相同方式替换阻塞适配器。
- 证书的「生成」动作与候选资格幂等/唯一性契约，以及课程操作资格判断，仍需在真实写接口下验证。
- `06-页面接口映射与联调阻塞.md` 的页面到接口状态表需同步更新：证书、评分、测试、控制台统计由「Mock 验收 / 已适配、待后端」更新为「HTTP_ADAPTED」。
