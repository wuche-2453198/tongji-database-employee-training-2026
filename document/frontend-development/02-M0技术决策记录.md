## 4. 边界规则

### 4.1 API 与 Mock

- 页面组件不得导入 Axios、拼接 Base URL 或读取原始 Mock 数据。
- 页面只消费 `services/` 暴露的前端服务接口和 `types/` 中的领域模型。
- HTTP DTO 放在 `api/`，与前端领域模型分离；字段差异只在映射层处理。
- Mock 和 HTTP 必须实现同一服务接口，通过环境配置选择。
- Mock 账号、凭证和场景只进入开发构建，不作为正式接口字段依据。

### 4.2 超时、取消与重试

- 默认超时为 10 秒，可通过非敏感环境变量调整。
- 页面卸载、查询条件变化或重复查询时允许取消旧请求。
- 幂等查询最多进行一次自动重试，并只针对明确可恢复的网络/服务错误。
- 创建、审批、签到、评分、证书等写操作不自动重试。
- 写操作超时或断线时显示“结果未知”，后续通过查询最终状态恢复，不直接再次提交。

### 4.3 质量门禁

- 本地与集成分支的统一检查命令为 `pnpm check`。
- 锁文件必须与 `package.json` 同步；安装验证使用 `pnpm install --frozen-lockfile`。
- 类型错误、ESLint 错误、格式检查失败、单元测试失败或构建失败均视为阻塞。
- Git Hook 暂不在 M1 强制安装，避免替团队成员修改本地 Git 配置；后续 CI 使用同一个 `pnpm check` 命令。

## 5. 等待后端确认

以下事项不阻塞 M0～M6，但阻塞 M7：

1. 使用 Token 还是 Cookie Session，以及刷新与退出失效机制。
2. CORS、`credentials`、CSRF 和认证头要求。
3. `/api/auth/me` 的最终用户、角色、权限和主角色结构。
4. 统一响应、字段错误、业务错误码与 `traceId` 的冻结格式。
5. 正式分页、搜索、排序、日期、时区与空值规则。
6. 真实联调地址、测试账号以及 401/403/404 的最终策略。
