# 页面接口映射与联调阻塞

## 1. 状态定义

状态统一使用以下令牌区分，避免把“前端完成”误读成“联调完成”：

| 令牌 | 含义 |
| --- | --- |
| `FRONTEND_DONE` | 页面、领域模型、服务接口与组件实现完成 |
| `MOCK_VERIFIED` | Mock 服务与自动化验收通过 |
| `HTTP_ADAPTED` | HTTP 适配器、DTO 映射已实现，待后端契约验证 |
| `INTEGRATION_DONE` | 真实后端环境联调通过 |
| `BLOCKED_BY_BACKEND` | 后端 Controller/DTO/OpenAPI 缺失或未冻结 |

正文沿用中文口径，对应关系如下：

- **已接入**（`HTTP_ADAPTED`）：当前仓库存在对应后端 Controller/DTO，前端已按源码实现适配；仍需真实环境账号完成运行验收（最终目标 `INTEGRATION_DONE`）。
- **已适配、待后端**（`HTTP_ADAPTED` + `BLOCKED_BY_BACKEND`）：`2026-09-10` 前后端合并完成后**已不再使用**；此前用于标记前端已实现、后端 Controller/OpenAPI 缺失的页面。
- **Mock验收**（`FRONTEND_DONE` + `MOCK_VERIFIED`，HTTP 侧 `BLOCKED_BY_BACKEND`）：`2026-09-10` 前后端合并完成后**已不再使用**；此前用于标记仅有 Mock、真实 HTTP 契约缺失的页面。

> 本节状态表与 `08-前后端合并与级联调试.md` 同步维护；历史上"已适配、待后端 / Mock验收"的页面已全部切换为真实 HTTP 契约。

## 3. 当前后端已确认契约

认证证据来自：

- `src/backend/TrainingManagement.Api/Controllers/AuthController.cs`
- `src/backend/TrainingManagement.Api/Dtos/Auth/LoginRequest.cs`
- `src/backend/TrainingManagement.Api/Dtos/Auth/LoginResponse.cs`
- `src/backend/TrainingManagement.Api/Dtos/Auth/AuthUserResponse.cs`
- `src/backend/TrainingManagement.Api/Common/Security/RoleCodes.cs`
- `src/backend/TrainingManagement.Api/Common/Security/PermissionCodes.cs`

确认结果：

- 登录字段是`Identifier`与`Password`，JSON适配为`identifier/password`。
- 登录返回`AccessToken`、`TokenType=Bearer`、`ExpiresAt`与当前用户。
- 当前用户包含`EmpId`、`EmpName`、部门、岗位、状态、角色集合和权限集合。
- 角色码为`ADMIN`、`HR`、`DEPT_MANAGER`、`EMPLOYEE`。
- 权限码为点号格式，例如`course.read`、`request.create`、`request.approve`、`request.file`。

## 5. 联调验收门禁

1. 对应后端模块合入并提供可追踪Swagger/OpenAPI。
2. 使用四角色真实账号验证200、401、403、404、409和503。
3. 验证后端数据范围：员工本人、主管本部门、HR授权范围。
4. 验证分页、空值、日期、枚举、字段错误和`traceId`。
5. 验证写操作并发、幂等或结果未知后的查询协议。
6. 只有真实环境测试通过后，才能把“已接入”更新为“联调通过”（`INTEGRATION_DONE`）。
7. 数据库不可达时统一返回 503 与“数据库暂时不可用”文案，便于联调快速定位，不再出现笼统 500。
