## 3. 实施原则

1. Figma和设计交付文档是视觉、交互、路由及状态依据，不按画面坐标硬编码页面。
2. 页面依赖前端领域模型和服务接口，不直接导入Mock JSON，不直接依赖后端传输字段。
3. Mock服务和真实HTTP服务实现同一前端服务接口，通过环境配置切换。
4. 权限同时作用于菜单、路由和操作入口，但后端鉴权仍是最终边界。
5. 所有列表和表单必须具备加载、空、失败、禁用、提交和恢复状态。
6. 写操作默认不自动重试；超时或断线时按“结果未知”处理并查询最终状态。
7. 凭证、密钥和真实环境地址不得提交到仓库。
8. 每个阶段通过验收后再进入下一阶段；后端阻塞不应被Mock数据掩盖或标记为已解决。

## 4. 工程启动前技术决策

工程创建前先形成轻量技术决策记录；下表默认方案不是最终结论，执行时应填写“确认结果”。

| 决策编号 | 决策项 | 建议默认方案 | 确认结果 | 状态 |
| --- | --- | --- | --- | --- |
| TD-001 | Node.js版本 | 当前LTS，并在`.nvmrc`或等价文件锁定 | Node.js 24 LTS，锁定`24.18.0` | 已确认 |
| TD-002 | 包管理器 | `pnpm`，提交唯一锁文件 | pnpm `11.19.0`，唯一`pnpm-lock.yaml` | 已确认 |
| TD-003 | 依赖版本策略 | 创建时锁定Vue、Vite、TS、Router、Pinia、Element Plus版本 | 直接依赖精确版本，间接依赖由锁文件冻结 | 已确认 |
| TD-004 | HTTP客户端 | `axios`或基于`fetch`的封装，页面不得直接调用 | Axios；页面只调用服务接口 | 已确认 |
| TD-005 | Mock方案 | 服务接口+内存Mock；是否增加MSW再决定 | 服务接口+内存Mock，当前不引入MSW | 已确认 |
| TD-006 | 单元/组件测试 | Vitest + Vue Test Utils | Vitest + Vue Test Utils + jsdom | 已确认 |
| TD-007 | E2E测试 | Playwright，基础路由与四角色流程优先 | Playwright，Chromium优先 | 已确认 |
| TD-008 | 代码质量 | ESLint + Prettier + TypeScript严格检查 | ESLint Flat Config + Prettier + TS严格模式，统一`pnpm check` | 已确认 |
| TD-009 | Element Plus引入 | 按需自动导入或显式导入二选一 | `unplugin-auto-import`+`unplugin-vue-components`按需自动导入 | 已确认 |
| TD-010 | 超时/重试 | 查询请求有限重试；写操作不自动重试 | 默认10秒；查询最多一次有限重试；写操作不重试 | 已确认 |

技术决策通过标准：不要求后端参与即可决定的项目全部关闭；涉及Cookie、跨域或认证头的部分明确标记“等待后端”。

## 5. 目标工程结构

```text
src/frontend/
├── README.md
└── training-management-web/
    ├── .env.example
    ├── .env.mock
    ├── .gitignore
    ├── package.json
    ├── pnpm-lock.yaml                # 若TD-002选择pnpm
    ├── tsconfig.json
    ├── vite.config.ts
    ├── index.html
    ├── public/
    ├── src/
    │   ├── api/                      # HTTP客户端、传输模型与适配器
    │   ├── assets/
    │   ├── components/
    │   │   ├── common/               # 通用视觉组件
    │   │   └── business/             # 可复用业务摘要组件
    │   ├── config/                   # 环境配置解析与校验
    │   ├── constants/                # 路由键、枚举展示等稳定常量
    │   ├── layouts/                  # AuthLayout、MainLayout
    │   ├── mocks/                    # Mock服务、场景与固定账号
    │   ├── router/                   # 路由表、元信息、守卫
    │   ├── services/                 # 页面消费的前端服务接口
    │   ├── stores/                   # auth、app等Pinia状态
    │   ├── styles/                   # tokens、Element主题、全局样式
    │   ├── types/                    # 前端领域模型与公共类型
    │   ├── utils/
    │   ├── views/
    │   │   ├── auth/
    │   │   ├── dashboard/
    │   │   ├── errors/
    │   │   └── placeholders/         # 业务路由占位页
    │   ├── App.vue
    │   └── main.ts
    ├── tests/
    │   ├── unit/
    │   └── e2e/
    └── README.md
```

`types/`中的领域模型与`api/`中的传输模型分离。真实接口冻结后，只在API映射和服务实现中处理字段差异，避免重写页面及Store。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Mock模型被误作正式DTO | 接口冻结后大面积返工 | 领域模型、传输模型、服务接口和Mock实现分层 |
| 认证方案变化 | Store、守卫和API客户端返工 | 页面只调用认证服务；凭证逻辑集中在单一适配层 |
| 过度封装Element Plus | 维护成本高、业务开发受限 | 只封装稳定交互模式，保留基础组件透传能力 |
| 权限只在菜单处理 | 直接访问路由产生越权体验 | 菜单、路由、按钮三层处理，真实安全依赖后端 |
| 写操作自动重试 | 重复审批、签到或证书 | 写操作默认不重试，结果未知时查询最终状态 |
| Figma与代码视觉漂移 | 验收返工 | 设计令牌集中管理，按阶段截图对比关键公共页 |
| Mock进入生产包 | 安全与演示数据泄露 | 构建配置隔离，生产构建检查Mock入口和固定账号 |
| 业务路由占位被视为已实现 | 进度误判 | 占位页显式标记状态，交付表区分基础与业务实现 |
