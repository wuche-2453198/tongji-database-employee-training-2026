## 1. 阶段定位

第 0 阶段是项目启动阶段，目标不是完成业务功能，而是把后续并行开发需要的技术、目录、数据库、接口、分支和文档约定先固定下来。

前端技术栈可以暂时待定，其余：

- 项目采用 B/S 架构。
- 前端只通过 HTTP API 调用 C# 后端。
- 前端不直接连接 Oracle。
- 后端通过 Oracle .NET 驱动访问 Oracle 数据库。

## 2. 总体目标

| 目标         | 说明                                        | 完成标志             |
| ---------- | ----------------------------------------- | ---------------- |
| 技术路线冻结     | 后端、数据库、数据库驱动、数据访问方式先确定；前端技术栈可保留待定项        | 形成技术选型记录         |
| 协作结构建立     | 明确目录结构、分支规范、README 维护方式、模块负责人边界           | 仓库结构和协作说明可见      |
| 数据库准备启动    | 确认 Oracle 免费版本、云服务器部署方案、Schema 规划和脚本目录    | 数据库负责人可以开始安装和写脚本 |
| 后端工程准备启动   | 确认 .NET SDK、Web API 项目结构、Oracle 驱动、统一响应格式 | 后端负责人可以创建项目骨架    |
| 接口约定初版     | 先统一 API 路径风格、响应格式、分页格式、错误格式、状态枚举          | 所有后端模块按同一套规则开发   |
| 第 1 阶段任务明确 | 把第 1 阶段“最小可运行系统”的任务拆到岗位                   | 每个负责人知道下一步交付物    |

## 4. 第 0 阶段不做的事情

- 不要求完成完整前端页面。
- 不要求实现所有业务接口。
- 不允许各模块在未统一响应格式、状态枚举和目录结构前各自随意开写。

## 5. 完成标准

第 0 阶段结束时，应满足以下条件：

- 技术选型记录已经写入文档，前端待定项有明确决策时间。
- 项目目录结构、Git 分支规则、README 维护方式已经确定。
- Oracle 免费版本、云服务器部署方案、Schema 和账号规划已经确定。
- 后端项目骨架目录、.NET SDK、Oracle 驱动和数据访问方式已经确定。
- API 统一响应格式、分页格式、错误格式和核心状态枚举已经确定。
- 员工、部门主管、HR、管理员四类角色权限边界已经有初版。
- 第 1 阶段每个岗位要交付什么已经明确。
