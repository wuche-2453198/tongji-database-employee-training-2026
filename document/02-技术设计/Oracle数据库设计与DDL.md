# Oracle 数据库设计与 DDL

本文是 13 张核心表、字段口径、迁移顺序和 Oracle DDL 的唯一执行基线。原始 [数据库设计文档.doc](../数据库设计文档.doc) 保留 E-R 图和初始需求，仅作历史参考；冲突时以本文为准。

## 1. 数据模型修正

1. `EMPLOYEES.DEPT_NAME` 外键改为 `DEPT_ID`，避免以可修改的部门名称建立关系。
2. 原需求要求登录但表中缺少登录名和密码字段；新增 `LOGIN_NAME`、`PASSWORD_HASH`，并增加直属主管 `MANAGER_EMP_ID`，以支持“仅本部门主管可审批”。
3. `TRAINING_REQUESTS` 的审批人与 HR 备案人改存员工 ID，不存姓名字符串；姓名由查询关联得到。
4. `TRAINING_REGISTRATIONS` 增加 `REQUEST_ID`，使“已备案申请”成为可追溯的报名依据。
5. `TRAINING_ATTENDANCE` 是签到时间、迟到分钟、扣减学时的唯一事实来源；报名表不重复保存签到时间和是否迟到。
6. E-R 文本中的“课程与讲师 N:M”与现有字段不一致。本期以 `TRAINING_COURSES.TRAINER_ID` 作为唯一主讲师，评分按该主讲师进行；不新增 `COURSE_TRAINERS`，避免无边界扩表。
7. `REMAIN_BUDGET` 不允许由页面或多个服务分别写入，改为 `ANNUAL_BUDGET - USED_BUDGET` 虚拟列。
8. `ROLES.PERMISSIONS` 不保存未被系统解析的 JSON。首期固定四种角色，权限策略由后端策略/特性统一维护；表仅存角色编码和名称。

## 2. 状态与一致性规则

| 对象 | 枚举 | 允许流转 / 判定 |
| --- | --- | --- |
| 员工 | `ACTIVE`, `RESIGNED` | 离职员工不得新建申请、报名、评分；历史记录保留 |
| 课程 | `DRAFT`, `PUBLISHED`, `CLOSED` | `DRAFT -> PUBLISHED -> CLOSED`；发布需主讲师、部门、时间地点、人数、学时、预算完整且部门余额充足 |
| 申请 | `PENDING`, `DEPT_APPROVED`, `DEPT_REJECTED`, `HR_FILED` | `PENDING -> DEPT_APPROVED/DEPT_REJECTED`，仅 `DEPT_APPROVED -> HR_FILED` |
| 报名 | `REGISTERED`, `SIGNED_IN`, `COMPLETED`, `ABSENT`, `CANCELED` | `REGISTERED -> SIGNED_IN/CANCELED/ABSENT`；`SIGNED_IN -> COMPLETED`；终态不可回退 |
| 黑名单 | `ACTIVE`, `RELEASED` | 生效黑名单禁止报名；每位员工同时最多一条生效记录 |
| 测试 | `PRE`, `POST` | 同员工、同课程、同类型仅一条 |
| 是否值 | `Y`, `N` | 全库统一，不使用“是/否”或布尔字符串 |

签到的固定算法：`lateMinutes = max(0, signInAt - courseStartAt)`；`deductHours = min(durationHours, floor(lateMinutes / 30) * 0.5)`；`actualHours = max(0, durationHours - deductHours)`。不足 30 分钟不扣学时，30 分钟扣 0.5 学时，之后每满 30 分钟再扣 0.5 学时。缺勤由 HR/管理员在课程结束后显式标记，不由前端自行判断。

课程发布和报名必须使用数据库事务。课程发布时锁定部门行，校验余额后同时更新课程与 `USED_BUDGET`。报名时先对课程行执行 `SELECT ... FOR UPDATE`，再统计有效报名（`REGISTERED`、`SIGNED_IN`、`COMPLETED`、`ABSENT`），确认未满员后插入。数据库唯一约束负责最终兜底，Service 负责返回可读的 409 业务错误。

### 3.2 `V001__init_schema.sql`

> 前提：Oracle 19c 或更高版本，推荐 Oracle Free 23ai / XE 21c；数据库字符集使用 `AL32UTF8`。执行账号为 `TRAINING_OWNER`，运行账号只授予 DML 权限。事件时间采用 `TIMESTAMP(0)`，日历日期采用 `DATE`，应用和数据库统一使用 `Asia/Shanghai` 时区。

```sql
ALTER SESSION SET NLS_LENGTH_SEMANTICS = CHAR;

CREATE TABLE DEPARTMENTS_TRAINING (
    DEPT_ID        NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
    DEPT_NAME      VARCHAR2(100) NOT NULL,
    BUDGET_YEAR    NUMBER(4) DEFAULT 2026 NOT NULL,
    ANNUAL_BUDGET  NUMBER(12,2) DEFAULT 0 NOT NULL,
    USED_BUDGET    NUMBER(12,2) DEFAULT 0 NOT NULL,
    REMAIN_BUDGET  NUMBER(12,2) GENERATED ALWAYS AS (ANNUAL_BUDGET - USED_BUDGET) VIRTUAL,
    CREATED_AT     TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    UPDATED_AT     TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT PK_DEPARTMENTS_TRAINING PRIMARY KEY (DEPT_ID),
    CONSTRAINT UQ_DEPARTMENTS_TRAINING_NAME UNIQUE (DEPT_NAME),
    CONSTRAINT CK_DEPT_BUDGET_YEAR CHECK (BUDGET_YEAR = 2026),
    CONSTRAINT CK_DEPT_ANNUAL_BUDGET CHECK (ANNUAL_BUDGET >= 0),
    CONSTRAINT CK_DEPT_USED_BUDGET CHECK (USED_BUDGET >= 0 AND USED_BUDGET <= ANNUAL_BUDGET)
);

CREATE TABLE EMPLOYEES (
    EMP_ID           NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
    LOGIN_NAME       VARCHAR2(50) NOT NULL,
    PASSWORD_HASH    VARCHAR2(255) NOT NULL,
    EMP_NAME         VARCHAR2(50) NOT NULL,
    DEPT_ID          NUMBER NOT NULL,
    MANAGER_EMP_ID   NUMBER,
    POSITION         VARCHAR2(50),
    EMAIL            VARCHAR2(100),
    PHONE            VARCHAR2(20),
    HIRE_DATE        DATE,
    STATUS           VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT       TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    UPDATED_AT       TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT PK_EMPLOYEES PRIMARY KEY (EMP_ID),
    CONSTRAINT UQ_EMPLOYEES_LOGIN_NAME UNIQUE (LOGIN_NAME),
    CONSTRAINT UQ_EMPLOYEES_EMAIL UNIQUE (EMAIL),
    CONSTRAINT FK_EMPLOYEES_DEPT FOREIGN KEY (DEPT_ID)
        REFERENCES DEPARTMENTS_TRAINING (DEPT_ID),
    CONSTRAINT FK_EMPLOYEES_MANAGER FOREIGN KEY (MANAGER_EMP_ID)
        REFERENCES EMPLOYEES (EMP_ID),
    CONSTRAINT CK_EMPLOYEES_STATUS CHECK (STATUS IN ('ACTIVE', 'RESIGNED')),
    CONSTRAINT CK_EMPLOYEES_LOGIN_LOWER CHECK (LOGIN_NAME = LOWER(LOGIN_NAME))
);

CREATE TABLE ROLES (
    ROLE_ID       NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
    ROLE_CODE     VARCHAR2(30) NOT NULL,
    ROLE_NAME     VARCHAR2(50) NOT NULL,
    CREATED_AT    TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT PK_ROLES PRIMARY KEY (ROLE_ID),
    CONSTRAINT UQ_ROLES_CODE UNIQUE (ROLE_CODE),
    CONSTRAINT UQ_ROLES_NAME UNIQUE (ROLE_NAME)
);

CREATE TABLE USER_ROLES (
    USER_ROLE_ID  NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
    EMP_ID        NUMBER NOT NULL,
    ROLE_ID       NUMBER NOT NULL,
    CREATED_AT    TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT PK_USER_ROLES PRIMARY KEY (USER_ROLE_ID),
    CONSTRAINT UQ_USER_ROLES_EMP_ROLE UNIQUE (EMP_ID, ROLE_ID),
    CONSTRAINT FK_USER_ROLES_EMP FOREIGN KEY (EMP_ID) REFERENCES EMPLOYEES (EMP_ID),
    CONSTRAINT FK_USER_ROLES_ROLE FOREIGN KEY (ROLE_ID) REFERENCES ROLES (ROLE_ID)
);

CREATE TABLE BLACKLIST (
    BLACK_ID      NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY,
    EMP_ID        NUMBER NOT NULL,
    REASON        VARCHAR2(500) NOT NULL,
    START_AT      TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    END_AT        TIMESTAMP(0),
    STATUS        VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT    TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    UPDATED_AT    TIMESTAMP(0) DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT PK_BLACKLIST PRIMARY KEY (BLACK_ID),
    CONSTRAINT FK_BLACKLIST_EMP FOREIGN KEY (EMP_ID) REFERENCES EMPLOYEES (EMP_ID),
    CONSTRAINT CK_BLACKLIST_STATUS CHECK (STATUS IN ('ACTIVE', 'RELEASED')),
    CONSTRAINT CK_BLACKLIST_PERIOD CHECK (END_AT IS NULL OR END_AT >= START_AT)
);
```

### 3.3 `V002__add_indexes.sql`

```sql

### 3.4 `V003__grant_app_privileges.sql`

```sql
BEGIN
    FOR t IN (
        SELECT TABLE_NAME
        FROM USER_TABLES
        WHERE TABLE_NAME IN (
            'DEPARTMENTS_TRAINING', 'EMPLOYEES', 'ROLES', 'USER_ROLES',
            'BLACKLIST', 'TRAINERS', 'TRAINING_COURSES', 'TRAINING_REQUESTS',
            'TRAINING_REGISTRATIONS', 'TRAINING_ATTENDANCE', 'TRAINER_RATINGS',
            'TRAINING_TESTS', 'TRAINING_CERTIFICATES'
        )
    ) LOOP
        EXECUTE IMMEDIATE 'GRANT SELECT, INSERT, UPDATE, DELETE ON '
            || DBMS_ASSERT.ENQUOTE_NAME(t.TABLE_NAME, FALSE)
            || ' TO TRAINING_APP';
    END LOOP;
END;
/
```

应用连接建立后执行 `ALTER SESSION SET CURRENT_SCHEMA = TRAINING_OWNER`，使未加 Schema 前缀的参数化 SQL 能解析到业务表。不得授予 `TRAINING_APP` 建表、删表或 DBA 权限。

### 3.5 `V004__blacklist_operator.sql`

```sql
-- 黑名单记录补充操作人审计字段（操作人可空，兼容既有历史数据）。
ALTER TABLE BLACKLIST ADD OPERATOR_EMP_ID NUMBER;

ALTER TABLE BLACKLIST ADD CONSTRAINT FK_BLACKLIST_OPERATOR
    FOREIGN KEY (OPERATOR_EMP_ID) REFERENCES EMPLOYEES (EMP_ID);
```

- **字段口径**：`OPERATOR_EMP_ID` 存操作人的员工 ID，不存姓名字符串；姓名由查询关联得到，与 §1 第 3 条一致。
- **可空**：既有历史记录不回填，因此不加 `NOT NULL`。
- **授权**：`V003` 已对 `BLACKLIST` 授予表级 DML 权限，新增列不需要重新授权。
- **已知待办**：该外键目前未建索引，与 `V002` 中"每个外键列都有索引"的惯例不一致；如需补齐，应新增 `V005`（已执行的迁移不可原地修改），索引名建议 `IDX_BLACKLIST_OPERATOR`。
- **执行前提示**：脚本不幂等，重复执行会报 `ORA-01430`（列已存在）。

## 4. 数据库运行规范

### 4.1 账号与权限

- `TRAINING_OWNER`：仅用于迁移、索引和授权。
- `TRAINING_APP`：应用运行账号，仅授予所需表的 `SELECT/INSERT/UPDATE/DELETE`；连接后设置 `CURRENT_SCHEMA=TRAINING_OWNER`。
- 不使用 DBA 账号运行应用，不在 Git 中提交真实密码或完整连接串。
- 云服务器安全组只开放必要来源和端口，数据库监听不得无范围暴露。

### 4.2 迁移规则

- 所有结构变更必须进入 `database/oracle/migrations/`，按版本递增且已经执行的脚本不可改写。
- 种子放在 `database/oracle/seed/`，验证查询放在 `database/oracle/samples/`。
- 每个脚本写明用途、作者、日期、前置版本和是否可重复执行。
- 后端实体、DTO、OpenAPI 和前端类型必须在字段或枚举变更时同步检查。
- 当前版本使用 identity column，不创建每表 Sequence 和主键触发器；若部署版本不支持 identity，必须在决策日志中记录兼容方案后统一切换。
- `UPDATED_AT` 的默认值只作用于插入。既然不使用触发器，每个更新 SQL 必须显式设置 `UPDATED_AT = SYSTIMESTAMP`。
- 已发布课程不得修改主讲师、主办部门、开始/结束时间、最大人数、学时和预算；关闭操作只改状态和更新时间。

### 4.3 种子数据

- `S001__roles_and_accounts.sql`：四角色和管理员、员工、主管、HR 测试账号，密码仅存 BCrypt 哈希。若显式指定 identity ID，须同步检查 identity 下一值不与种子冲突；优先让数据库生成 ID，再通过唯一业务键关联后续种子。
- `S002__basic_data.sql`：至少 3 部门、8 员工、3 讲师、5 课程。
- `S003__demo_flow.sql`：备案、报名、签到、完成、评分、测试和证书历史样例。
- 种子数据必须可重复构造已知演示环境，不使用真实员工隐私数据。
- 所有测试登录名以小写写入；本期 `BUDGET_YEAR` 固定为 2026，不接受其他年度预算数据。

### 4.4 备份与验证

- 每次大联调前保留可恢复 baseline；最终集成版本生成 `demo-ready`。
- `S001__verification.sql` 至少检查 13 表计数、孤儿外键、重复活跃申请/报名、预算透支、分数越界和重复证书。
- 从空 Schema 执行迁移和种子的完整日志是数据库就绪条件；恢复演练成功是发布前条件。
