## 使用规则

1. 开工顺序以“项目执行与人员分工”为准，技术实现以“技术架构与开发规范”和“Oracle 数据库设计与 DDL”为准，是否可合并和发布以“测试联调与发布验收”为准。
2. 原始 `.doc` 与归并后的 Markdown 冲突时，以归并后的 Markdown 为执行口径；需要改变执行口径时，必须先形成决策记录。
3. 同一规则只在所属文档中维护。其他文档使用链接引用，不复制整段内容。
4. 数据库字段和状态枚举遵守已通过的决策。接口可在开发期调整，但模块最终验收前必须统一检查 DDL、后端 DTO/Swagger、前端类型、页面映射和测试用例。
5. 真实密码、云服务器私钥、生产连接串和个人本地路径不得写入任何文档。

## 当前已确认范围

- 本期交付范围为 2026 年单年度部门预算、一门课程一名主讲师、一次课程一次签到。
- 主链路固定为：课程发布 -> 申请 -> 主管审批 -> HR 备案 -> 报名 -> 签到/完成 -> 评分/测试 -> 证书。
- 后端使用 ASP.NET Core Web API，前端使用 Vue 3，数据库使用 Oracle；详细版本与依赖见技术规范。
- 核心数据模型保留 13 张表，修正登录、部门外键、审批人、报名依据和数据一致性问题。
- 跨年度预算、多讲师、真实二维码、邮件通知和复杂统计不进入首期关键路径。

## 文档变更流程

文档变更与代码变更可分步提交，但模块最终验收 PR 必须包含或关联完整文档。文档提交说明使用 `docs(模块): 说明`。已经进入联调的字段、状态或接口变更必须在 PR 中列出影响范围、兼容方式和需要重跑的测试。
